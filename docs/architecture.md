## 1. Overview

This project implements a containerized monitoring stack designed for infrastructure observability in a Security Operations Center (SOC) environment. The system collects real-time metrics from host systems, visualizes them through dashboards, and generates alerts based on defined thresholds.

The stack is deployed using Docker Compose for Level 1, enhanced with security features for Level 2, and orchestrated using Kubernetes for Level 3.

---

## 2. Selected Stack and Justification

The selected stack includes:

* **Prometheus** – Metrics collection and time-series database
* **Grafana** – Visualization and dashboarding
* **Alertmanager** – Alert routing and notification
* **Node Exporter** – System metrics exporter
* **Nginx (Level 2)** – Reverse proxy and TLS termination

### Justification

This stack is widely used in production environments and aligns with SOC and DevOps practices. It provides:

* Real-time monitoring
* Alert-based detection
* Scalable architecture
* Integration with security workflows

---

## 3. System Components

### 3.1 Prometheus

Prometheus is responsible for scraping metrics from monitored targets such as Node Exporter. It stores the data in a time-series database and evaluates alert rules.

### 3.2 Grafana

Grafana connects to Prometheus and provides dashboards for visualizing system metrics such as CPU, memory, and disk usage.

### 3.3 Alertmanager

Alertmanager processes alerts generated by Prometheus and routes them to configured receivers. It supports grouping and deduplication of alerts.

### 3.4 Node Exporter

Node Exporter runs on the host system and exposes system-level metrics such as CPU usage, memory consumption, and disk I/O.

### 3.5 Nginx (Level 2)

Nginx acts as a reverse proxy to route external traffic to internal services and provides TLS encryption for secure communication.

---

## 4. Architecture Design

The system follows a multi-tier architecture:

* **Presentation Layer:** Grafana dashboards accessed via browser
* **Application Layer:** Prometheus and Alertmanager
* **Monitoring Layer:** Node Exporter

All components communicate over internal Docker networks, ensuring isolation and controlled access.

---

## 5. Network Design

Two networks are used:

### Frontend Network

* Services: Nginx, Grafana
* Accessible from external users

### Backend Network

* Services: Prometheus, Alertmanager, Node Exporter
* Internal communication only

### Port Assignments

| Service       | Port     | Access   |
| ------------- | -------- | -------- |
| Grafana       | 3000     | External |
| Prometheus    | 9090     | Internal |
| Alertmanager  | 9093     | Internal |
| Node Exporter | 9100     | Internal |
| Nginx         | 443 / 80 | External |

This segmentation reduces the attack surface by restricting direct access to backend services.

---

## 6. Storage Design

Persistent storage is implemented using Docker volumes and Kubernetes PersistentVolumeClaims.

### Stored Data:

* Prometheus metrics data
* Grafana dashboards and configurations

This ensures that data is retained across container restarts and system failures.

---

## 7. Security Considerations

The system includes several security measures:

* Use of environment variables for credentials
* No hardcoded secrets in configuration files
* Network segmentation between frontend and backend
* TLS encryption via Nginx (Level 2)
* Limited port exposure

These measures help protect against unauthorized access and improve system security.

---

## 8. Scalability

The architecture is designed to scale:

* Docker Compose supports vertical scaling
* Kubernetes enables horizontal scaling with replicas
* Prometheus and Grafana can be replicated for high availability

This allows the system to handle increased load and larger environments.

---

## 9. Monitoring and Alerting Strategy

The system supports proactive monitoring:

* CPU and memory usage tracking
* Disk utilization monitoring
* Service availability checks

### Example Alerts:

* High CPU usage (>80%)
* High memory usage
* Target down

These alerts help detect potential issues and support SOC operations.
